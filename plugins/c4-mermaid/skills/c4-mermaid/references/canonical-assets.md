# Mandatory canonical C4 assets

The user-supplied [native palette XML](../assets/drawio-c4/reference-palette.drawio) is the authoritative asset set. Always use it for C4 architecture; it is not an optional theme or a rough visual reference. Its original bytes and digest are preserved. The source page name is user-provided data; all authored instructions and template titles are English.

- [native-c4.mxlibrary](../assets/drawio-c4/native-c4.mxlibrary) contains 18 reusable native entries, including the supplied legend. Import it locally in draw.io using File > Open Library from > Device. No remote library is required.
- [native-templates.json](../assets/drawio-c4/native-templates.json) contains the exact 17 supplied object styles and metadata. Runtime helpers read this snapshot; the verifier checks its source digest.
- [provenance](../assets/drawio-c4/provenance.json), original upstream source, complete [Apache-2.0 license](../assets/drawio-c4/LICENSE.drawio), and [notice](../assets/drawio-c4/NOTICE.txt) are included for offline use and redistribution.

Use Person2 for both person variants, with the distinct internal/external colors; rounded blocks for System, Container, and Component; cylinder3 for Data Container; cylinder3 with `direction=south` for Message Bus; hexagon with the supplied settings for Microservice Container; WebBrowserContainer2 for browser containers. Logical System/Container scopes are gray dashed rounded frames, with labels at the bottom. Every diagram includes a visible native table-style color key plus explanations of the actual shapes, boundaries, and arrows. Organizational and deployment primitives must remain explicitly distinct; they are additions outside this supplied logical C4 palette.

Keep exact native geometry identifiers and defining style properties. Changing dimensions, wrapping labels, selecting readable font colors, and reserving caption/routing space are permitted to satisfy readability. Do not replace supplied shapes with generic custom stencils, image cells, terminal windows, UML component tabs, or invented bucket/folder silhouettes. Do not infer microservice status from a repository folder or Docker image; justify the abstraction and presentation subtype from evidence.

The supplied XML is a notation palette, not application architecture evidence. Placeholder names, unattached sample arrows, and title metadata are not project facts. Instantiate independent editable native cells; give them evidence-based names, real parents, attached relationships, and consistent type metadata. Keep labels and metadata synchronized after editing.

Mermaid cannot load a draw.io shape library. Use the canonical palette's semantic mapping and colors in Mermaid, disclose unsupported glyph/boundary adaptations, and always accompany a C4 architecture view with its exact native `.drawio` artifact. Do not claim a Mermaid-only approximation satisfies exact asset fidelity. Code/sequence views retain appropriate UML/sequence notation; never force class or lifeline semantics into C4 container glyphs. When the native exporter does not support a required view, author the correct native view locally and disclose any rendering limit.
